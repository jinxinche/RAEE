## Measure the result

Record the actual post URL and publication time once it exists. Compare repository views, unique visitors and referrers for clearly recorded date windows; GitHub's Traffic view uses a rolling window, not permanent campaign attribution. Record meaningful replies, reproducible issue reports and reported installation attempts separately. Keep account-only analytics in private notes.

After the first post, prioritize fixes reported by real readers. A useful follow-up is a documented improvement from that feedback, rather than repeated copies of the initial announcement. Stars, visits and clone counts are different signals; no growth target is promised by this kit.
